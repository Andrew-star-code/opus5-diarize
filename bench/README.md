# Стенд замеров диаризации

Качество диаризации нельзя оценить на глаз по своим записям: у них нет
правильного ответа, с которым можно сравнить. Здесь оно меряется на
записях с эталонной разметкой — трёх встречах корпуса AMI (по 4
участника, английский). Диаризация различает голоса, а не слова, поэтому
на русский цифры переносятся приблизительно, но сравнивать варианты
настройки между собой по ним можно честно.

Главная метрика — **DER**, доля времени, где говорящий определён неверно.
Складывается из пропущенной речи, ложной речи и путаницы говорящих.
Для транскрипта, где у каждого слова один автор, важнее всего путаница:
это ровно те слова, которые пользователь увидит под чужим именем.

## Как запустить

```bash
bash bench/fetch_ami.sh
```

Сервисные воркеры на время замера лучше остановить — стенду нужна
видеопамять:

```bash
docker compose stop worker-live worker-batch
```

```bash
docker compose run --rm --no-deps -v "$(pwd)/bench:/bench" worker-batch python -u /bench/eval_round3.py /bench/data
```

`eval_round3.py` считает по коду самого воркера — проверяет ровно то,
что уходит пользователю. Он берёт распознанные слова из кеша, который
создаёт `eval_round2.py`, поэтому при первом запуске сначала выполните
его (распознавание трёх встреч занимает несколько минут, дальше — из
кеша).

| Скрипт | Что меряет |
|---|---|
| `eval_diarization.py` | Настройки пайплайна: порог кластеризации, склейку пауз, эксклюзивную и обычную разметку, известное число говорящих |
| `eval_round2.py` | Слияние лишних говорящих по сетке порогов, сглаживание по частям, источник меток для слов |
| `eval_round3.py` | Итог: как было и как стало, по production-коду |
| `eval_live.py` | Живая диаризация (diart): настройки кластеризации, задержка, способ собирать разметку в сегменты |

## Живая диаризация

`eval_live.py` меряет, сколько слов живой черновик отдаёт не тому
говорящему. Опорная разметка здесь — не AMI, а чистовики ваших же
записей: batch-пайплайн работает офлайн и заведомо точнее потокового, так
что близость к нему — честная мера отставания живого режима. Запись, у
которой чистовик сам ненадёжен, помечается в скрипте и в среднее не
входит.

Опорная разметка выгружается из базы в `bench/cache/live_refs.json`:
для каждой сессии путь к звуку относительно `data/` и слова
`[начало, конец, говорящий]` — без текста. Каталог `bench/cache/` в
репозиторий не попадает.

Считается в два этапа. Дорогая часть — сегментация и эмбеддинги каждого
окна — от настроек не зависит и считается один раз на видеокарте. Дальше
кластеризация, склейка окон и порог diart прогоняются по кешу на
процессоре, параллельно: сотня конфигураций — пара минут. Слова
раздаются говорящим тем же кодом выравнивания WhisperLiveKit, что и в
живом режиме.

```bash
docker compose run --rm --no-deps -v "$(pwd)/bench:/bench" worker-live python -u /bench/eval_live.py cache
```

```bash
docker compose run --rm --no-deps -v "$(pwd)/bench:/bench" worker-live python -u /bench/eval_live.py eval grid --mode fixed --rhos 0.05 0.1 0.15 0.2 --deltas 0.9 1.0 1.1 --latency 0.5 1.0 1.5
```

Этап `variants` сравнивает способы сборки сегментов при значениях diart по
умолчанию, `grid` — сетку порогов, `one` — одну конфигурацию.
