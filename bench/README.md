# Стенд замеров диаризации

Качество диаризации нельзя оценить на глаз по своим записям: у них нет
правильного ответа, с которым можно сравнить. Здесь оно меряется на
записях с эталонной разметкой — трёх встречах корпуса AMI (по 4
участника, английский). Диаризация различает голоса, а не слова, поэтому
на русский цифры переносятся приблизительно, но сравнивать варианты
настройки между собой по ним можно честно.

Главная метрика — **DER**, доля времени, где говорящий определён неверно.
Складывается из пропущенной речи, ложной речи и путаницы говорящих.
Для транскрипта, где у каждого слова один автор, важнее всего путаница:
это ровно те слова, которые пользователь увидит под чужим именем.

## Как запустить

```bash
bash bench/fetch_ami.sh
```

Сервисные воркеры на время замера лучше остановить — стенду нужна
видеопамять:

```bash
docker compose stop worker-live worker-batch
```

```bash
docker compose run --rm --no-deps -v "$(pwd)/bench:/bench" worker-batch python -u /bench/eval_round3.py /bench/data
```

`eval_round3.py` считает по коду самого воркера — проверяет ровно то,
что уходит пользователю. Он берёт распознанные слова из кеша, который
создаёт `eval_round2.py`, поэтому при первом запуске сначала выполните
его (распознавание трёх встреч занимает несколько минут, дальше — из
кеша).

| Скрипт | Что меряет |
|---|---|
| `eval_diarization.py` | Настройки пайплайна: порог кластеризации, склейку пауз, эксклюзивную и обычную разметку, известное число говорящих |
| `eval_round2.py` | Слияние лишних говорящих по сетке порогов, сглаживание по частям, источник меток для слов |
| `eval_round3.py` | Итог: как было и как стало, по production-коду |
| `eval_live.py` | Живая диаризация (diart): настройки кластеризации, задержка, способ собирать разметку в сегменты |
| `eval_sortformer.py` | Прогон NVIDIA Streaming Sortformer по тем же записям — для сравнения с diart в `eval_live.py compare` |
| `eval_asr.py` | Распознавание русского: Whisper large-v3 (как в чистовике) против GigaAM-v3 |

## Живая диаризация

`eval_live.py` меряет, сколько слов живой черновик отдаёт не тому
говорящему. Опорная разметка здесь — не AMI, а чистовики ваших же
записей: batch-пайплайн работает офлайн и заведомо точнее потокового, так
что близость к нему — честная мера отставания живого режима. Запись, у
которой чистовик сам ненадёжен, помечается в скрипте и в среднее не
входит.

Опорная разметка выгружается из базы в `bench/cache/live_refs.json`:
для каждой сессии путь к звуку относительно `data/` и слова
`[начало, конец, говорящий]` — без текста. Каталог `bench/cache/` в
репозиторий не попадает.

Считается в два этапа. Дорогая часть — сегментация и эмбеддинги каждого
окна — от настроек не зависит и считается один раз на видеокарте. Дальше
кластеризация, склейка окон и порог diart прогоняются по кешу на
процессоре, параллельно: сотня конфигураций — пара минут. Слова
раздаются говорящим тем же кодом выравнивания WhisperLiveKit, что и в
живом режиме.

```bash
docker compose run --rm --no-deps -v "$(pwd)/bench:/bench" worker-live python -u /bench/eval_live.py cache
```

```bash
docker compose run --rm --no-deps -v "$(pwd)/bench:/bench" worker-live python -u /bench/eval_live.py eval grid --mode fixed --rhos 0.05 0.1 0.15 0.2 --deltas 0.9 1.0 1.1 --latency 0.5 1.0 1.5
```

Этап `variants` сравнивает способы сборки сегментов при значениях diart по
умолчанию, `grid` — сетку порогов, `smooth` — правила «обрывок не меняет
говорящего» поверх лучших порогов, `snap` — подтяжку границы к концу
предложения (нужен текст слов четвёртым полем в `live_refs.json`), `one` —
одну конфигурацию.

Кроме доли слов под чужим именем стенд считает дробление: сколько реплик
в черновике против чистовика и сколько из них обрывки короче трёх слов.
Одной доли ошибок мало — настройка может снизить её и при этом
раздробить текст так, что его невозможно читать.

Встречи AMI из `bench/data` (после `fetch_ami.sh`) попадают в `eval_live.py`
автоматически: для них считается строгий DER против разметки, сделанной
людьми, — без воротника вокруг границ и с учётом перекрытий, как в
опубликованных замерах. Правила сглаживания работают со словами и на DER
не влияют.

## Streaming Sortformer

Сквозная потоковая модель диаризации NVIDIA (2025): звук идёт порциями,
говорящие держатся в кеше в порядке появления. Её советует сам
WhisperLiveKit вместо diart. NeMo несовместим с diart (numpy), поэтому
у неё отдельный образ:

```bash
docker build -t scribe-bench-sortformer bench/sortformer
```

```bash
docker run --rm --gpus all -v "$(pwd)/bench:/bench" -v "$(pwd)/data:/data" -v "$(pwd)/models:/models" -v "$(pwd)/worker-live:/live" -e HF_HOME=/models scribe-bench-sortformer python -u /bench/eval_sortformer.py
```

Сегменты складываются в `bench/cache/sortformer/`: `lat*` — эталонный
потоковый прогон NeMo (`diarize()`), `stream*` — класс живого режима
`worker-live/sortformer_stream.py` на том же звуке кусками по 0,1 с. Для
второго в контейнер монтируется код воркера: `-v "$(pwd)/worker-live:/live"`.
По кадрам они совпадают на 99,9–100%.

Считает их `eval_live.py eval compare` — тем же выравниванием и
сглаживанием, что и diart. В штатном образе worker-live нет
`pyannote.metrics` (он нужен для DER на AMI) — его ставим на время
прогона:

```bash
docker compose run --rm --no-deps -v "$(pwd)/bench:/bench" worker-live sh -c 'pip install -q "pyannote.metrics==3.2.*" && python -u /bench/eval_live.py eval compare'
```

Строки diart в этом образе пропускаются: diart из него убран (numpy
ниже 2 против NeMo 3). Этапы `cache`, `variants`, `grid`, `smooth`,
`snap`, `phantom` для diart требуют образа с ним — его можно собрать из
коммита до перехода на Sortformer. Последние результаты diart рядом с
Sortformer сохранены в `bench/cache/live_results_compare_diart.jsonl`.

### Запаздывание смены говорящего

Этапы `boundary` и `lag` отвечают на вопрос «почему начало фразы нового
говорящего достаётся предыдущему». На каждой смене говорящего по
чистовику считается, сколько первых слов новой реплики (до пяти) ушло
предыдущему и сколько последних слов прежней — новому.

На семи записях (194 смены) Sortformer без всяких правил отдаёт начало
реплики предыдущему в 43% смен, а обратная ошибка — в 17%: перекос
систематический. Правило четырёх слов его усиливает (48%): на стыке
метка дрожит, и короткие куски начала реплики уходят назад. Перенос к
концу предложения, наоборот, помогает (23%). Вместе — 31%.

Сдвиг разметки раньше (`lag`) выравнивает перекос около 0,16 с, но по
разметке людей на AMI модель по времени точна: DER растёт уже со
сдвига 0,16 с. Сдвиг на один кадр модели (0,08 с) на стенде выглядел безопасным: на своих
записях ошибка 14,0% → 13,0%, начало реплики уходит предыдущему в 26%
смен вместо 31%, DER на AMI не меняется. Правило четырёх слов с
заглядыванием вперёд (кусок начала реплики отдаётся следующей длинной
реплике того же говорящего) проверено и отброшено: начало реплики
спасает чуть лучше, но в целом ошибается больше.

Стенд берёт время слов из чистовика, а в живом режиме его даёт
потоковый распознаватель. Поэтому решение проверено сквозным замером
(`live_boundary_e2e.py`): пять записей через `/ws/live` в реальном
времени, слова черновика сопоставляются со словами чистовика по тексту.

| Живой режим | Слов под чужим именем | Начало ушло предыдущему | Конец ушёл новому |
|---|---|---|---|
| без сдвига | **12,6%** | 39% смен | 29% смен |
| сдвиг 0,08 с | 15,9% | 35% смен | 30% смен |

Сдвиг вредит, и он не принят. В живом режиме перекоса почти нет:
граница промахивается в обе стороны на слово-два — разметка видит смену
кадрами по 80 мс с порцией 0,32 с, а потоковый распознаватель ставит
время слов приблизительно. Точные границы даёт чистовик.

Запуск — в начале `live_boundary_e2e.py`.

## Распознавание русского

`eval_asr.py` сравнивает Whisper large-v3 (кодом самого batch-воркера,
ровно как в чистовике) с GigaAM-v3 в двух вариантах: с пунктуацией и
без. Наборы:

- **Golos farfield** — дальний микрофон, 1916 фраз. GigaAM учили в том
  числе на Golos, так что ему здесь проще;
- **FLEURS ru** — чтение фраз из Википедии; ни одна модель его не видела.

Метрики — доля ошибок в словах (WER) и буквах (CER) после приведения к
одному виду: нижний регистр, ё → е, цифры словами, без пунктуации.
Наборы скачиваются в `bench/data/asr/` (Golos — parquet с Hugging Face,
FLEURS — `data/ru_ru` из `google/fleurs`). Образ — batch-воркер плюс
GigaAM:

```bash
docker build -t scribe-bench-asr bench/asr
```

```bash
docker run --rm --gpus all -v "$(pwd)/bench:/bench" -v "$(pwd)/models:/models" -e HF_HOME=/models scribe-bench-asr python -u /bench/eval_asr.py
```

### Результат

| | Golos (дальний микрофон) | FLEURS (чтение) |
|---|---|---|
| Whisper large-v3 (как в чистовике) | 16,1% | **4,0%** |
| GigaAM-v3 с пунктуацией | **5,9%** | 4,5% |

Доля ошибок в словах. На нейтральном FLEURS Whisper не хуже. Выигрыш
GigaAM на Golos во многом объясняется данными: это команды голосовому
помощнику («Салют», «Джой», «Афина…»), на которых GigaAM учили. Вторая
причина — галлюцинации Whisper на коротких шумных фразах: вместо команды
он пишет «Субтитры сделал DimaTorzok» или «Редактор субтитров…». На
FLEURS он дважды дописал такую подпись в конец настоящей фразы. Эти
строчки теперь вырезаются и из черновика, и из чистовика
(`hallucinations.py`): на Golos фильтр изменил 32 фразы, на FLEURS — ровно
те две, убрав только подпись; у GigaAM — ни одной.

Менять распознавание в чистовике эти данные повода не дают. Вариант
GigaAM без пунктуации (`v3_rnnt`) в сравнение не вошёл: его файл дважды
скачивался с сервера не целиком и не проходил контрольную сумму.
