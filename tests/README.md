# Тесты

Пять скриптов без внешнего фреймворка — их можно запустить где угодно,
в том числе внутри контейнера, где pytest не установлен. Каждый печатает
построчный отчёт и возвращает ненулевой код при провале.

## Слияние ASR и диаризации

Чистая логика, зависимостей нет — запускается прямо на хосте:

```bash
py -3 tests/test_merge.py
```

Проверяет назначение говорящего по временному перекрытию, разбиение на
реплики по паузам и длине, запасной путь без пословных таймингов.

```bash
py -3 tests/test_tiny_speakers.py
```

Проверяет слияние лишних говорящих — обрывков чужого голоса, которые
диаризация выделяет в отдельного человека. Главный случай взят с
эталонной встречи AMI, где модель нашла пятерых вместо четырёх. Остальные
проверки следят, чтобы правило не трогало настоящих участников: тихого
человека со своим голосом и того, кто похож голосом, но говорил заметно.
Отдельно — сворачивание цепочек слияния и устойчивость к пустым и
испорченным эмбеддингам. Там же проверяется, что сглаживание по
умолчанию выключено.

```bash
py -3 tests/test_smooth.py
```

Проверяет сглаживание коротких вставок чужого говорящего. В сервисе оно
**выключено** по результатам замера на эталонных записях (см. `bench/`):
на реальных встречах короткие вставки чаще оказываются настоящими
репликами, и сглаживание увеличивало долю слов с неверным говорящим.
Тест остаётся, чтобы функция не сломалась для тех, кто включит её
параметром `SMOOTH_SPEAKER_TURNS`.

## Сквозной тест backend

Поднимает приложение с временной базой и проходит оба сценария целиком:
живая запись с доводкой, загрузка файла, редактирование текста и
говорящих, статистика, все шесть форматов выгрузки, удаление.

Запускать в контейнере — там уже есть все зависимости:

```bash
docker compose run --rm --no-deps -v "$(pwd)/tests:/tests" -e PYTHONPATH=/srv backend python /tests/test_backend.py
```

58 проверок. Временные файлы и база создаются во временном каталоге и
удаляются в конце, боевые данные не затрагиваются.

## Живая диаризация

Регрессионная проверка бага, при котором во всех живых записях, кроме
первой после старта воркера, все шли «Спикером 1». Гонит отрывок с двумя
голосами в `/ws/live` с реальной скоростью — несколько записей подряд
или одновременно — и завершается с ошибкой, если у какой-то записи
оказался один говорящий. Нужны работающий worker-live и поток с диалогом
в формате webm/opus в каталоге `data/`:

```bash
docker compose cp tests/live_diarization_check.py worker-live:/srv/
```

```bash
docker compose exec worker-live python /srv/live_diarization_check.py seq 2 /data/stream_dialog.webm
```

Записи попадают в библиотеку с заголовком «Проверка диаризации — можно
удалить».

## Качество диаризации

Это не тесты, а замеры на записях с эталонной разметкой — они в `bench/`.
